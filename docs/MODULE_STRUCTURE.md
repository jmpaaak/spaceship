# 모듈 구조 — 거대 단일 파일 금지 (2026-09-07)

기능 개발 때 기존 거대 파일에 동작을 계속 붙여 넣지 않는다.
새 기능은 담당 모듈 파일로 분리하고, 씬/엔트리는 `require`만 한다.

이 문서는 스켈레톤에서 파생된 모든 LÖVE 프로젝트(`spaceship`, `man-of-korea`, 이후 게임)와
자율 루프 `loop/PROMPT.md`의 원본이다. PROMPT에는 한 단락만 두고 여기로 보낸다.

## 한도

- 한 Lua 파일이 **800줄 또는 80KB**를 넘으면, 그 사이클의 작업은 기능 추가가 아니라
  **모듈 분리 리팩토링**이다. GREEN+커밋 전에 그 파일에 새 기능을 넣지 마라.
- 슬라이스 = **모듈 1개**. 예: `game/scenes/play_hud.lua`, `game/ui/slot.lua`,
  `game/ui/shop.lua`, `story/foo.lua`.
- `play.lua` / `main.lua` / `self_test.lua`를 더 키우지 마라.
  `self_test`는 시나리오별 상위 함수 또는 `game/tests/<topic>.lua`.
- 순수 규칙(`game/*.lua`, `love.*` 없음)과 씬 드로우를 섞지 마라.

## INBOX 최대 병렬 (사용자 2026-09-07)

처리 대기 목록을 **가능한 단위로 최대로** 워크트리 병렬화한다.

1. 각 INBOX 항목에 **담당 파일/모듈**을 명시한다 (루프가 레인 배정하려면 필수).
2. 터치 파일이 겹치지 않는 항목은 각각 `git worktree add` + 전용 브랜치 + 레인 `PROMPT.md`.
3. 같은 거대 파일을 만지는 항목은 **그 파일을 모듈로 쪼개기 전까지 직렬**.
4. 모듈 분해가 병렬도의 전제다. `play.lua`를 HUD/슬롯/상점/부스트/헬프로 나누면
   그 다음 사이클부터 그 수만큼 레인을 올린다.
5. **예외 — 이미 독립인 항목은 모듈화를 기다리지 말고 즉시 WT:**
   JSON+전용 모듈, `tools/` 에디터, 에셋 생성 스크립트, 순수 `game/*.lua`(씬 비의존).
6. 한 레인 = 한 모듈 또는 한 독립 디렉터리. 같은 파일을 두 레인이 동시에 만지면 금지.
7. 메인 워크트리의 dirty `play.lua`/`expedition.lua`에는 강제 checkout/pull 금지.
   슬라이스는 레인에서 푸시하고 메인 트리에서 merge.

## 새 기능 체크

1. 이 동작이 들어갈 **새 또는 기존 작은 모듈** 이름을 정한다.
2. 거대 씬 파일에는 `require` + 한 줄 위임만 추가한다.
3. 테스트는 그 모듈을 직접 require한다 (씬 전체를 로드하지 않아도 되게).
4. INBOX 한 줄에 담당 모듈 경로를 적는다 — 적지 않으면 루프가 전부 `play.lua`에 붙여
   병렬이 1레인이 된다.
